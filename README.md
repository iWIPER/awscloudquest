# AWS Cloud Quest

**An interactive game for exploring cloud computing and AWS concepts.**

AWS Cloud Quest is a software engineering project exploring how game mechanics can be used to make cloud computing concepts more engaging, interactive, and accessible.

The project aims to combine structured challenges, progressive difficulty, and practical cloud scenarios in a cohesive learning experience.

## Overview

Cloud computing involves a broad range of services, architectural decisions, security principles, and operational practices. Understanding how these components work together requires more than memorizing service definitions.

AWS Cloud Quest explores a challenge-based approach to learning, where players progress through scenarios designed around cloud architecture, service selection, infrastructure, and problem-solving.

## Objectives

- Design an extensible game architecture.
- Translate cloud computing concepts into interactive challenges.
- Introduce AWS services through scenario-based learning.
- Apply software engineering principles throughout development.
- Evaluate opportunities for secure and cost-conscious AWS integration.

## Core Concepts

The project is intended to explore the following areas:

| Domain | Focus |
|---|---|
| Compute | Virtual machines and serverless workloads |
| Storage | Object storage and data persistence |
| Networking | Cloud networking and connectivity |
| Security | IAM, permissions, and least privilege |
| Databases | Relational and NoSQL data services |
| Observability | Monitoring, logs, and operational visibility |
| Architecture | Service selection and system design |

These are intended learning domains; individual modules will be documented as they are implemented.

## Engineering Principles

The project will prioritize:

- **Modularity:** Separate gameplay, challenge definitions, and infrastructure concerns.
- **Maintainability:** Keep the codebase organized and documented.
- **Security:** Avoid hardcoded credentials and apply least-privilege access.
- **Testability:** Validate core logic and challenge evaluation.
- **Scalability:** Keep future integrations and new game modules in mind.
- **Cost awareness:** Evaluate AWS resource costs before deployment.

## Technology Stack

The implementation stack will be documented after the initial architecture and framework have been selected.

AWS services will be introduced where they provide a concrete technical benefit rather than being added solely for the sake of using cloud infrastructure.
